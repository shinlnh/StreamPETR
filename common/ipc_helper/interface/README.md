# ADAS Service Interface
## General architecture
```txt
                +-------------------------------------+
                |      ADAS Service Interface         |
                |  (contain list of Topic Interface)  |
                +-------------------------------------+
                                 |
        +------------------------+----------------------+  
        |                        |                      |
        v                        v                      v
+-----------------+     +-----------------+    +-----------------+    
|  Topic Handler  |     |  Topic Handler  |    |  Topic Handler  |
|       IMU       |     |      GNSS       |    |       ...       |
+-----------------+     +-----------------+    +-----------------+
```

## How to add new Topic Handler for ADAS Service Interface
### 1. Create the ROS message for new topic (Optional)
All ROS messages are located at `$SDK_PATH/ipc_helper/src/msg`
- Message files are used to determine the class name of the autogenerated code. As such, they must be CamelCased. e.g. `CarStatus.msg`
- Message fields should be lowercase with underscore separation. e.g. `hand_brake`

Sample message:
```
# GnssPoint.msg
uint64 timestamp
float32 x
float32 y
float32 z
```
### 2. Create new topic handler
All the Topic Handler headers are located at `$SDK_PATH/common/ipc_helper/interface/inc`. Naming rule is **snake_case**. The format is `topic_<topic_name>.h`

***Note:*** If the topic needs to implement complex functionality, feel free to create a new file in the src folder.

Sample topic handler:
```C++
#ifndef TOPIC_IMU_H
#define TOPIC_IMU_H

// ROS header
#include <rclcpp/rclcpp.hpp>

// Message header
#include <ipc_helper/msg/imu_parameters.hpp>

// System header
#include <functional>
#include <string>

class TopicImuHandler : public rclcpp::Node
{
private:
    rclcpp::Publisher<ipc_helper::msg::ImuParameters>::SharedPtr publisher_;
    rclcpp::Subscription<ipc_helper::msg::ImuParameters>::SharedPtr subscriber_;
    std::string topic_name_;
public:
    TopicImuHandler(std::string vehicle_name = "hero0") : Node("topic_handler_imu") {
        topic_name_ = "/adas/" + vehicle_name + "/imu";
        publisher_ = this->create_publisher<ipc_helper::msg::ImuParameters>(topic_name_, 10);
        subscriber_ = this->create_subscription<ipc_helper::msg::ImuParameters>(
            topic_name_, 10, 
            [](const ipc_helper::msg::ImuParameters::SharedPtr msg){
                (void)msg;  // avoid warning unused parameter
            }
        );    }
    ~TopicImuHandler() {}

    void registerCallback(std::function<void (const ipc_helper::msg::ImuParameters::SharedPtr msg)> callback)
    {
        subscriber_ = this->create_subscription<ipc_helper::msg::ImuParameters>(
            topic_name_, 10,
            callback
        );
    }
    void publish(const ipc_helper::msg::ImuParameters &msg)
    {
        publisher_->publish(msg);
    }
};

#endif // TOPIC_IMU_H
```
### 3. Integrate topic hanler to ADAS Service Interface
- Add the header of new topic handler to `$SDK_PATH/common/ipc_helper/inc/adas_service_if.h`
- Add new topic's name to `enum class TopicNameT` (make sure `COUNT` at the end of list)
- Modify the method `void AdasServiceIF::registerTopic(const TopicNameT &topic_type)`
### 4. Modify the CMakeLists.txt
- If creating a new `.cpp` file, adding this file to function `add_executable()` of all `CMakeLists.txt` use the ADAS Service Interface.
- If the new topic need more dependence packages, adding all packages to `$SDK_PATH/ipc_helper/src/package.xml`
```xml
<!-- Example: -->
<package format="3">
  ...
  <depend>std_msgs</depend>
  <depend>geometry_msgs</depend>
  ...
</package>
```

## How to use ADAS Service Interface in ROS bridge
General ADAS ROS Bridge architecture
```txt
                    +--------------------------+
                    |        <package>         |
                    |       adas_bridge        |
                    +--------------------------+
                                 |
        +------------------------+----------------------+  
        |                        |                      |
        v                        v                      v
+-----------------+     +-----------------+    +-----------------+    
|  <executable>   |     |   <executable>  |    |   <executable>  |
|      imu        |     |       gnss      |    |       ...       |
+-----------------+     +-----------------+    +-----------------+
```
Each executable must contain only 1 ROS node. Therefore, ADAS Service Interface just provide topic's name instead of fully API to create and manage new ROS node.
### 1. Create name for the new topic
In `adas_service_if.h`, add the base name of each topic to `topic_name_str_` and its corresponding alias to `enum class TopicNameT`. Ensure that the order of both entries matches exactly. 

Example: The topic's name is `/adas/hero0/imu` &Rightarrow; The base name of topic is `imu`. The alias can be the uppercase version: `IMU`
```C++
std::vector<std::string> topic_name_str_ = {
    "imu",
    "gnss",
    "radar_front",
    "vehicle_control_cmd",
    "vehicle_manual_control_cmd",
    "service_status",
    "visualization",
    "car_status"
};
enum class TopicNameT : int {
    IMU = 0,
    GNSS,
    RADAR,
    CONTROL,
    MANUAL_CONTROL,
    SERVICE_STATUS,
    VISUALIZATION,
    CAR_STATUS,
    COUNT
};
```
### 2. Use in ROS Bridge
- Create `AdasServiceIF` instance
- Get topic's name 
- Create publisher/subscriber
```C++
// ADAS Service Interface instance
std::unique_ptr<AdasServiceIF> adas_service_if_;
rclcpp::Publisher<ipc_helper::msg::ImuParameters>::SharedPtr adas_publisher_;

// Create publisher/subscriber
adas_service_if_ = std::make_unique<AdasServiceIF>(vehicle_name, prefix);
adas_publisher_ = this->create_publisher<ipc_helper::msg::ImuParameters>(
    adas_service_if_->getTopicName(AdasServiceIF::TopicNameT::IMU), 
    10
);
```
